# المرحلة الرابعة — إعدادات الإنتاج والتكامل

هذه الوثيقة لتجهيز البيئة فقط. لا تضع أسرارًا حقيقية داخل Git أو ملفات الواجهة.

## 1) إعدادات الواجهة العامة
- راجع `Shared/supabase-config.js`: المسموح في الواجهة فقط Project URL ومفتاح publishable/anon.
- لا تضع `service_role` أو أي secret key داخل `Store/` أو `Dashboard/` أو `Shared/`.
- اضبط عنوان المتجر والداشبورد الحقيقيين في أسرار Supabase Functions كما هو موضح أدناه.

## 2) أسرار Edge Functions
من لوحة Supabase > Edge Functions > Secrets (أو CLI secrets set)، اضبط القيم وفق عناوين النشر الفعلية:

- `FLORA_DASHBOARD_ORIGIN`: أصل لوحة الإدارة فقط، مثل `https://admin.example.com` (مثال توضيحي؛ استبدله بعنوانك).
- `FLORA_CUSTOMER_AUTH_ORIGINS`: قائمة Origins مسموحة مفصولة بفواصل، مثل `https://shop.example.com,https://www.example.com`.
- احتفظ بمفاتيح Supabase السرية في مخزن الأسرار فقط، ولا تشاركها في المحادثة.

**مهم:** أسماء المتغيرات يجب أن تطابق ما تقرؤه ملفات الوظائف. لا تنشر قبل التأكد من ذلك في آخر مرحلة.

## 3) نشر الوظائف
بعد ضبط الأسرار، انشر الوظائف من مجلد المشروع الذي يحتوي `Backend/supabase/config.toml` باستخدام Supabase CLI، مع مراجعة أسماء المشاريع والـ project ref يدويًا قبل النشر. لا تستخدم أمرًا يتضمن `--project-ref` قبل التأكد من أنه المشروع الصحيح.

## 4) البريد والإشعارات
- راجع Supabase Auth > URL Configuration: Site URL وRedirect URLs لتطابق الدومينات الفعلية.
- إن كان تسجيل الدخول يعتمد OTP أو بريدًا، اضبط SMTP موثوقًا وحدود الإرسال وقالب الرسالة من لوحة Supabase.
- تنبيه الطلبات الحالي داخل الداشبورد يعتمد على فتح الصفحة والتحديث الدوري؛ لا تعتبره Push Notification بعد إغلاقها.
- لا تضف مزود إشعارات خارجيًا قبل تحديد المزود ومفاتيحه وتكلفته وسياسة الخصوصية.

## 5) النسخ الاحتياطي والاستعادة
- فعّل خطة النسخ الاحتياطي المناسبة لمشروع Supabase وتحقق من مدة الاحتفاظ المتاحة في خطتك.
- قبل أي ترحيل SQL، خذ نسخة احتياطية قابلة للاستعادة من أدوات Supabase/pg_dump الموثقة، واحفظها خارج المستودع في مكان مقيد الصلاحيات.
- وثّق من يملك صلاحية الاستعادة، وتاريخ آخر نسخة، ومدة الاستعادة المستهدفة.
- لا تشغّل `Backend/supabase/reset_store_data.sql` ضمن التجهيز أو النسخ الاحتياطي؛ هذا الملف قد يحذف بيانات المتجر.
- لا تستخدم SQL يدويًا لمحاكاة نسخة احتياطية؛ النسخة الصحيحة يجب أن تشمل البيانات المطلوبة ومخططها وأن تُختبر استعادتها في بيئة منفصلة في المرحلة الأخيرة.

## 6) إعداد النشر
- تأكد أن Vercel Root Directory يشير إلى المجلد الذي يحتوي `vercel.json`.
- اربط الدومين، HTTPS، وراجع إعدادات Redirect URLs وCORS وفق الدومين النهائي.
- راجع سياسات الاحتفاظ بالسجلات وعدم تسجيل كلمات مرور أو رموز OTP أو مفاتيح.

## 7) ما لم يتم فعله
لم يتم نشر الوظائف إلى مشروع Supabase، أو تعديل أسرار حسابك، أو أخذ نسخة احتياطية من قاعدة البيانات الفعلية، أو اختبار إرسال البريد؛ هذه العمليات تتطلب وصولًا لحساباتك. الاختبارات الشاملة مؤجلة للمرحلة الخامسة حسب الخطة.
